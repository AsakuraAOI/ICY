# ICY Agent 自编写插件：最小自动化方案

状态：已于 2026-09-27 部署到 ICY 服务器并为一个明确的私聊 OpenID 启用；本地、服务器离线测试与真实 QQ 插件创建验收均已通过。

## 核心选择

新增一个 `plugin-writer` App Module。它让 Agent 编写的是可调用的功能插件：接收 JSON、返回 JSON。例如文本处理、格式转换、数据整理。生成代码由独立 Node 子进程按需执行。

主 Agent 始终只看到三个固定工具：`plugin_create`、`plugin_list`、`plugin_run`。新插件保存后由 `plugin_run` 按名称调用，不向 ToolRegistry 动态注册工具，因此不需要热加载、重启机器人或改变 QQ 插件发现机制。

这里把生成目标从外层 QQ 事件插件调整为 Agent 功能插件，是为了让新增能力直接进入 Agent 的工具循环。回复仍由原 Agent 完成，无需处理多个 QQ 插件的优先级和回复冲突。

## 自动闭环

```text
用户提出需求
  -> Agent 查询已有插件
  -> 没有合适能力时编写源码和测试案例
  -> plugin_create：语法检查、子进程测试；可传 inputJson 立即调用
       失败：返回具体错误，Agent 修正后重试
       成功：保存插件并返回名称
  -> plugin_run：后续复用该插件时调用
  -> Agent 根据真实结果回复用户
```

正常使用无需手动审查、安装或发布。失败的草稿不启用，已有插件继续可用。沿用现有 Agent 的模型调用数、工具调用数和总时间限制，耗尽就结束，不建立另一套后台任务系统。

## 三个工具

| 工具 | 参数 | 行为 |
|---|---|---|
| `plugin_list` | 无 | 返回当前用户可用插件的名称、用途、输入说明 |
| `plugin_create` | name、description、source、testsJson、可选 inputJson | 校验和试跑，通过后保存；提供 inputJson 时一并返回本轮运行结果；同名同源码重试可复用 |
| `plugin_run` | name、inputJson | 在独立子进程执行，返回 JSON 结果或有界错误 |

`inputJson` 和 `testsJson` 首版使用 JSON 字符串，工具内部解析和验证，适配现有工具参数校验器；不为此引入一整套 JSON Schema 框架。执行身份来自 ToolContext，不允许模型传入 owner 或文件路径。

插件文件使用 `.mjs`，只约定一个导出：

```js
export default async function run(input) {
  return { text: String(input.text).trim() };
}
```

代码先支持 Node 内置能力，不自动安装 npm 依赖。模型必须说明输入格式，并给出至少一个输入/预期输出测试案例。固定 runner 导入插件、调用函数、序列化结果；生成代码不需要自己实现 IPC 或生命周期。它不能注册 QQ 事件或修改 Agent 本身。

## 保存和执行

每个插件只需源码与元数据两个文件，保存在运行数据目录的 `generated-plugins/<owner>/<name>/`；owner 由程序根据已验证身份映射，name 只允许简单字符。每次调用按需启动 Node，不维护常驻插件进程。

创建时先写临时目录，执行 `node --check`，再用相同 runner 运行测试。返回 JSON 与预期结果做深度比较；宿主额外检查输出是否可序列化、大小是否超限。成功后原子移动到正式目录，只有正式目录会被列出和调用。模型提供的测试能发现常见错误，不代表已证明所有业务语义正确。

子进程默认 5 秒超时、256 MiB V8 堆上限、16 KiB 输出上限；堆上限不是整个进程的内存配额。Node 的 `--permission` 只允许读取 runner 与本插件源码，不开放文件写入或子进程能力。超时或取消时终止进程，不让它继续占住 Agent。测试也使用同样限制，并服从当前 Run 剩余时间。运行错误作为结构化工具结果返回，使 Agent 能据此改正；同名同源码的重试返回已有结果，修改源码需使用新名称。

这些生成插件是自动执行的本地代码。首版仅向配置好的管理员身份开放创建和执行工具；开关启用后不逐次确认。子进程使用最小环境，不传模型密钥或 QQ 凭证。Node 权限模型和子进程限制了常见文件访问与崩溃影响，但不是完整的系统沙箱，不能隔离所有同用户权限。

## 实际需要改的地方

- 新增 `plugin-writer` 模块、固定 runner 和文件存储帮助函数，复用现有 Models/Agent 循环，不增加独立编写服务。
- 在现有 ToolDefinition 中允许 write 类型，并在 Policy 中明确授权这三个工具。创建和执行都按有副作用的操作处理，不能假装只读来绕过现有检查。
- 模块 setup 时注册三个固定工具，仍遵守 ToolRegistry 启动后冻结的规则。策略配置增加管理员列表；WebUI 的 enabledTools 校验同步接受三个工具名，避免保存其他设置时拒绝配置。首版不增加插件管理页面。
- 给 Agent 一段简短使用说明：先复用已有插件，确有需要再创建，创建通过后调用，失败看错误修正，不能声称未执行的结果。源码保存在文件里，list 只返回简短说明，避免每轮携带全部插件代码。

使用 `plugin_create.inputJson` 后，正常的“查找 → 创建并运行 → 回答”可在 3 次模型调用、2 次工具调用内完成。若要自动修正生成失败的代码，仍应把预算调到至少 5 次模型调用、3 次工具调用。源码长度受当前模型单次生成耗时影响，首版选择小插件，不自动拆分大工程。启用方式见 README；运行时需要支持 `--permission` 的 Node。

## 验收

用一次请求跑通“列出能力 -> 创建文本处理插件并返回首次运行结果 -> 回复真实结果”，随后另一请求用 `plugin_run` 复用它。再验证语法错误可修正、失败草稿不可调用、重复名称不覆盖、普通用户不可访问、死循环在超时后终止、重启后插件仍可用。

首版不加入独立服务、任务队列、审批流、版本库、发布平台或热加载。出现具体需求后再增加功能：确实要更新同名插件时加备份替换；需要面向普通用户执行时再设计权限隔离；需要 QQ 事件插件时再扩展另一种插件类型。

## HiAgent Provider 适配核对（2026-09-27）

部署前的基线为 `/opt/icy/releases/20260927-keywords`：WebUI 设置使用 `hiagent-chat` / `deepseek-v4.1-flash`，每轮 3 次模型调用、2 次工具调用、输出上限 512；run 时限为 210 秒，OpenAI 传输层未单独配置 `timeoutMs`，所以每次模型请求默认 30 秒。当前发布目录为 `/opt/icy/releases/20260927-plugin-writer`，已注册三个插件工具；模型/工具调用上限调整为 5/3，HiAgent 模型单次超时配置为 90 秒，输出上限 512 保持不变。不要把本地仓库的默认值当作线上配置。

用线上相同的 OpenAI 入口做了不安装插件的只读兼容测试：Provider 返回含 `name/description/source/testsJson/inputJson` 的完整 `plugin_create` 工具调用（约 3.4 秒），随后接受模拟的 tool 结果并正常给出最终答复（约 3.5 秒）。这证明短插件的工具参数和结果可以往返；没有证明长源码生成或线上 QQ 实际安装已通过。

本模块让 `plugin_create.inputJson` 在校验后执行一次并返回结果，使“先 list，再 create+run，最后回答”落在原 3 次模型调用、2 次工具调用预算内；线上调到 5/3 给一次失败修正留余量。Provider 的 [兼容性文档](../../hiagent-coding-provider/docs/compatibility.md)说明 `max_tokens` 不会转发到上游，较长生成受约 270 秒的 Provider 截止时间约束；ICY 的 90 秒请求超时现在先于 Provider 截止时间。上线后仍要观察真实 QQ 插件任务的耗时和被动回复窗口，不把服务 READY 当作最终验收。

线上验收：授权用户在 QQ 私聊中要求创建并运行文本大写插件，机器人返回实际结果 `HI`；run 元数据为 `completed / sent`，持久目录中存在 `upper_text` 的源码与元数据，记录了 2 个通过的测试。此前的服务器发布版保留为可回滚版本，私有环境与设置文件也有发布前备份。
